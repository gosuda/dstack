# Do it now

Finish the complete authorized scope in this run. The user asked to finish now, ship now, clear active todos, or unblock undone work with no phases and no TODO-later remainders. Internal sequencing may organize the work; it never divides the deliverable into staged rollouts, follow-up PRs, or deferred remainders.

## Your authority comes from the assignment, not from this skill

An implementation request permits its authorized reversible local changes. A plan-only or read-only request permits the complete plan or analysis, never implementation. Nothing here grants authority to commit, publish, deploy, use credentials, spend, discard data, or change public contracts; those run only on explicit human invocation for that action. Plan-only stays plan-only.

## Start from the existing scope and backlog

Use the current specification or plan directly when it establishes scope, constraints, and acceptance criteria; do not demand a new planning or question round. Refresh active todos, open tasks, undone implementation, claimed blockers, and usable worker outputs from the task list, plan, and working tree. Refreshing the backlog never expands scope beyond what the ask authorizes. Resolve repository and tool facts directly. Ask only when an unresolved choice materially changes the outcome or the next action needs authority the user has not granted.

## Close what is done, clear what is stale

Check each claimed-complete item against its actual state and acceptance evidence, not its list status. Close only what the evidence supports; reopen the rest as open work. Re-examine each claimed blocker against the current tree, configuration, captured output, and completed work. A blocker whose condition no longer holds is cleared with the evidence that clears it. One held only by an outdated status, an old log, or a superseded assumption gets re-tested through an authorized observation before it is allowed to stop anything.

## Account for the whole ask, then execute in dependency order

List the requested outcomes, acceptance criteria, affected consumers, and approval boundaries. Never redefine the task around the easiest subset. Dispatch independent ready work, use internal phases and separate local commits when authorized, delegate when useful, and carry integration through to final delivery. A finished internal phase, a worker return, or an updated task list is progress, never a stopping condition.

## Ship real behavior on every required path

Migrate affected callers and remove obsolete paths inside the authorized scope. Finish required tests and documentation. No TODO, stub, placeholder, raised NotImplemented, or labels such as foundation, phase 2, later, or follow-up may stand in for requested behavior. Finding such a remainder means writing the real implementation.

Drive each remaining blocker with the next authorized action that produces new information or changes the blocking condition. Salvage every usable partial worker output instead of discarding it. An actionable blocker is work to execute, never a reason to stop; do not convert an executable next step into advice for the user or a remainder for another turn. Failed edits or verification on owned work get repaired in the source, preserving unrelated and intervening user changes rather than restoring a stale file over them.

## Reconcile, prove, and return

Check every acceptance criterion against the integrated result, including error paths and affected consumer contracts, and confirm every backlog item closed with evidence or reported as blocked. Obtain completion evidence after the last relevant change using only assignment-permitted verification; read the result and exit status where applicable. Source presence, compilation, and worker assurances never substitute for a required behavior check. Return the completed deliverable with concise evidence of what exists and works now. When verification is prohibited, finish the permitted deliverable and state exactly which claims remain unverified; never run a prohibited check and never claim unperformed checks passed.

## Stay honest about scope and blockers

Never cut scope for size, inconvenience, or a phase boundary, and never expand it because the backlog surfaced adjacent ideas. When a genuine constraint forces a scope change, state the concrete conflict, the exact proposed change, and its consequences, then wait for user approval; until then the original scope stands, and only coherent in-authority work continues meanwhile. Never ship reduced scope first and report it as done.

When completion depends on an unavailable prerequisite or ungranted authority, finish independent reachable work, preserve a coherent local state, and report the exact missing prerequisite, the affected outcome, and what enables continuation. A truthful blocker is not a placeholder, and a partial result is not complete. Fabricated evidence never substitutes for a missing observation.
