# 수동 평가 사례

각 사례를 새 세션에서 독립적으로 실행하고 출력과 판정 근거를 기록합니다.
원문과 출력의 의미를 대조하며, 문장 수만으로 통과 판정을 내리지 않습니다.
정답 문장과 바이트 단위로 대조하지 않으며, 아래 필수 조건의 충족 여부로만 판정합니다.

## 판정 원칙

각 사례는 다음 세 판정 중 하나로 기록합니다.

- `통과`
- `실패`
- `판정 보류`

조건, 의무 수준, 수치, 위험 등급, 작업 순서가 변경되면 치명적 실패로 판정합니다.
모호한 핵심 지시를 확정하지 않고 확인을 요청한 결과는 유효한 결과로 판정합니다.
고정 원문을 보존한 예외와 누락된 위반을 구분합니다.

## 순서가 확인된 독립 행동

입력: `한국어 STE로: 운영자는 설정 파일을 저장한 다음 서버를 다시 시작해야 합니다.`

필수 조건: 운영자의 두 행동을 구분하고, 저장 후 재시작의 순서를 유지합니다.
실패: 두 행동을 `설정을 반영하십시오`로 통합하거나 순서를 뒤바꿉니다.

## 여러 단계의 공통 조건

입력: `절차로 바꿔 줘: 승인을 받은 경우에만 A를 제출한 다음 B를 제출하십시오.`

필수 조건: 승인 조건을 두 행동 모두에 적용하고, A 다음 B의 순서를 보존합니다.
실패: B를 승인 없이 제출할 수 있는 무조건 지시로 변경합니다.

## 필요조건

입력: `통제 한국어로: 점검 모드일 때만 파일을 삭제할 수 있습니다. 별도의 삭제 권한도 필요합니다.`

필수 조건: 점검 모드와 삭제 권한을 모두 필요조건으로 유지합니다.
실패: 점검 모드이면 즉시 삭제하라고 지시합니다.

## 동시 수행

입력: `한 단계에 한 행동으로 정리해 줘: 잠금 버튼을 누른 상태를 유지하면서 손잡이를 돌리십시오.`

필수 조건: 누른 상태의 유지와 회전 동작의 결합을 보존합니다.
실패: 버튼을 누르고 놓은 뒤 돌려도 되는 순서로 변경합니다.

## 알려지지 않은 주체의 설명문

입력: `STE 원칙으로: 전송 중 데이터가 손상되었습니다. 손상 원인은 아직 확인하지 못했습니다.`

필수 조건: 설명문으로 유지하며, 행위 주체나 원인을 추가하지 않습니다.
실패: 사용자가 데이터를 손상했다고 서술하거나 데이터 손상을 지시합니다.

## 고정 경고문

입력: `절차를 정리해 줘. 다음 경고는 고정 문구이므로 변경하지 마: "주의: 파일 삭제 후 복구할 수 없습니다." 작업은 "파일을 삭제하십시오."다.`

필수 조건: 경고 문구와 `주의` 등급을 그대로 보존하고 해당 작업 앞에 배치합니다.
실패: 등급을 `위험`으로 변경하거나 새 예방 조치를 사실로 추가합니다.

## 안전 지시의 첫머리

입력: `절차로 다듬어 줘: 주의: 이 장비는 고전압을 사용하므로 커버를 열기 전에 전원을 차단해야 합니다.`

필수 조건: 주의 문장을 `커버를 열기 전에 전원을 차단하십시오`처럼 명령 또는 조건으로 시작하고, 위험 내용을 이어서 서술합니다. `주의` 등급을 유지합니다.
실패: 위험 설명이 지시보다 앞에 남습니다. 등급을 변경하거나 원문에 없는 예방 조치를 추가합니다.

## 새로운 용어의 상태

입력: `이 문서에서 "적용"은 저장된 설정을 실행 중인 서버에 반영하는 작업이다. "저장"과 구분해서 용어를 통일해 줘.`

필수 조건: 저장과 적용을 별도 개념으로 유지하고 문서 내 정의로 취급합니다.
실패: 두 개념을 동일한 행동으로 통합하거나 ASD의 승인 용어라고 표시합니다.

## 두 의미로 사용된 단어

입력: `STE로 다듬어 줘: 압력계의 표시를 확인하십시오. 작업 계획은 팀장의 확인을 받은 후 시작하십시오.`

필수 조건: `확인`을 점검의 의미로만 사용하고, 팀장의 행위는 `승인`처럼 다른 단어로 서술합니다. 두 단계를 별도로 유지합니다.
실패: 출력에 승인의 의미로 사용된 `확인`이 남습니다. 팀장의 승인을 점검 작업으로 바꿉니다.

## 종결형의 정리

입력: `STE로 다듬어 줘: 백업 파일을 보관해 두도록 하십시오. 케이블은 분리하지 않도록 합니다. 시스템이 로그를 기록하고 있게 됩니다.`

필수 조건: 지시는 `백업 파일을 보관하십시오.`, 금지는 `케이블을 분리하지 마십시오.`, 설명은 `시스템이 로그를 기록합니다.`처럼 허용된 종결형으로 서술합니다.
실패: 보조 용언을 겹친 종결형이 남습니다. 금지를 권고로 약화하거나 시스템 동작을 작업 지시로 바꿉니다.

## 긴 절차 문장의 분리

입력: `한국어 STE로: 점검 모드로 전환한 후 서비스 상태 페이지에서 오류 표시가 있는지 확인하고 오류 표시가 없으면 설정 파일을 서버에 적용한 다음 로그에서 적용 결과를 확인하십시오.`

필수 조건: 조건, 행동, 결과를 기준으로 15어절 이하의 단계로 분리합니다. `오류 표시가 없으면` 조건을 적용 단계에 유지하고 순서를 보존합니다.
실패: 15어절을 넘는 단계가 사유 없이 남습니다. 적용 단계에서 조건이 빠집니다. 원문에 없는 오류 분기를 추가합니다.

## 상한을 넘는 조건 문장

입력: `한국어 STE로: 냉각수 온도가 40°C 이하이고 압력계가 0 kPa를 표시하는 동안에만 잠금 버튼을 누른 상태로 배수 밸브 손잡이를 돌리십시오.`

필수 조건: 지속 조건과 동시 동작을 하나의 지시로 유지하고, 검토 보고에 상한 초과 사유를 기재합니다.
실패: 조건을 첫 단계에만 적용되도록 분리합니다. 상한 초과 사유를 기재하지 않습니다.

## 명사 연쇄의 해소

입력: `STE로 다듬어 줘: 서버 설정 파일 백업 상태 점검을 수행하십시오. 백업 서버 로그 정리를 하십시오.`

필수 조건: 첫 문장은 `서버 설정 파일의 백업 상태를 점검하십시오.`처럼 조사와 동사로 관계를 드러냅니다. 두 번째 문장은 수식 관계를 판단할 수 없으므로 확인 사항으로 보고합니다.
실패: 명사가 네 개 이상 이어지는 구가 남습니다. 근거 없이 수식 관계를 하나로 정합니다.

## 개조식 종결의 복원

입력: `절차로 정리해 줘: 작업 전 전원 차단 요망. 설정 변경 시 관리자 승인 받을 것. 로그 파일 삭제하십시오.`

필수 조건: 각 문장을 조사와 서술어를 갖춘 `~하십시오` 지시로 서술합니다. 승인 조건을 설정 변경 앞에 유지합니다.
실패: 출력 본문에 `~요망`, `~할 것`, `~함` 종결이나 생략된 조사가 남습니다. 원문에 없는 주체나 대상을 추가합니다.

## 파괴적 작업의 모호함

입력: `STE로 완성해 줘: 잠시 기다린 뒤 필요한 데이터를 초기화하십시오. 대상과 종료 기준은 정해지지 않았습니다.`

필수 조건: 핵심 절차의 확정을 보류하고 대상, 종료 기준, 초기화의 의미를 확인합니다.
실패: 시간, 경로, 삭제 방식, 초기값을 임의로 삽입합니다.

## 경계값과 정밀도

입력: `정리해 줘: 측정값이 0.0500을 초과하면 거부합니다. 정확히 0.0500이면 허용합니다. 설정 리터럴 "0.0500"은 유지합니다.`

필수 조건: 초과 조건과 경계값의 포함 여부를 유지하고, 보호된 리터럴 `0.0500`을 그대로 둡니다.
실패: `이상`으로 변경하거나 리터럴을 `0.05`로 변경합니다.

## 코드, 경로, UI 문자열의 보호

입력: `다듬어 줘: "Run check" 버튼으로 검사를 시작하십시오. 종료 코드가 0인지 확인하십시오. /srv/app/config.toml의 dry_run = true는 수정하지 마십시오.`

필수 조건: UI 문자열, 종료 코드, 경로, 설정 구문을 그대로 보존하며, 작업을 실제로 실행하지 않습니다.
실패: 버튼 이름을 번역하거나 설정값을 변경합니다.

## 자동 동작과 사용자 행동

입력: `STE로: 운영자는 검사를 시작합니다. 시스템은 검사 결과를 자동으로 저장합니다.`

필수 조건: 검사를 시작하는 주체와 결과를 저장하는 주체를 구분합니다.
실패: 운영자에게 검사 결과 저장이라는 새 작업을 부여합니다.

## 단계 분리와 교차 참조

입력: `다음 작업을 단계별로 다듬어 줘. 1단계: A를 저장한 다음 B를 제출하십시오. 2단계: B 제출이 실패하면 1단계 전체를 다시 수행하십시오. 재시도 시 A 저장도 반복하는 것이 요구사항입니다.`

필수 조건: 행동을 분리한 뒤에도 재시도 범위를 A 저장과 B 제출 전체로 유지합니다.
실패: 번호를 변경한 뒤 이전 번호를 그대로 두어 재시도 범위가 A 저장만으로 축소됩니다.

## 의무를 흐리는 상투 표현

입력: `STE로 다듬어 줘: 배포 전 백업 확인을 진행해 주시면 감사하겠습니다. 운영 정책상 백업 확인은 필수입니다.`

필수 조건: 형식 동사를 제거하고, 정책이 명시한 의무를 `배포하기 전에 백업을 확인해야 합니다` 또는 단계형 `백업을 확인하십시오`로 서술합니다.
실패: 요청 표현이 남아 의무가 권고로 읽힙니다. 백업 위치나 확인 방법을 추가합니다.

## 상투적 대조 구문의 분리

입력: `STE로 다듬어 줘: 설정 파일은 삭제하는 것이 아니라 보관하십시오. 이 단계는 단순한 정리가 아닌 감사 대비 절차입니다.`

필수 조건: `설정 파일을 보관하십시오.`라는 행동 단계와 `설정 파일을 삭제하지 마십시오.`라는 별도 금지 단계를 둡니다. 단계의 성격은 `이 단계는 감사 대비 절차입니다.`와 같이 긍정문으로 서술합니다.
실패: 출력에 `A가 아니라 B`, `단순한 A가 아닌 B`, `A라기보다는 B`, `A뿐만 아니라 B` 중 하나가 남습니다. 삭제 금지가 누락됩니다.

## 사선 병기의 해소

입력: `절차로 정리해 줘: 로그 및/또는 설정 파일을 백업하십시오. 결과는 성공/실패로 기록하십시오. 백업 위치는 /srv/backup/입니다.`

필수 조건: `및/또는`의 결합 방식에 근거가 없으므로 해당 단계를 확정하지 않고 확인을 요청합니다. 기록 값은 `성공` 또는 `실패`처럼 관계를 명시하여 서술합니다. 경로 `/srv/backup/`은 그대로 보존합니다.
실패: 출력에 `및/또는`, `성공/실패` 같은 사선 병기가 남습니다. 근거 없이 한 가지 뜻을 선택합니다. 경로의 사선을 변경합니다.

## 양비론적 유보의 보류

입력: `절차로 바꿔 줘: 재시작은 무중단 방식일 수도 있고 전체 재시작일 수도 있습니다. 상황에 따라 다릅니다. 둘 다 장단점이 있습니다.`

필수 조건: 재시작 단계를 확정하지 않습니다. 재시작 방식을 정하는 조건이 원문에 없음을 보고하고, 결정 조건과 조건별 방식을 확인 사항으로 기록합니다.
실패: 근거 없이 한 방식을 선택하여 지시합니다. 결정 조건을 추가합니다. 출력에 `상황에 따라 다릅니다`나 `장단점이 있습니다`가 결정 없이 남습니다.

## 결정 조건이 제시된 양비론적 유보

입력: `절차로 바꿔 줘: 접속 중인 사용자가 있으면 무중단 재시작을 하고, 없으면 전체 재시작을 합니다. 두 방식 모두 장단점이 있습니다.`

필수 조건: 접속 사용자 확인 단계와 두 조건별 재시작 단계를 명시적 조건문으로 서술하고, `장단점이 있습니다` 문장을 삭제합니다.
실패: 조건 하나를 누락합니다. `상황에 따라`와 같은 표현으로 조건을 흐립니다. 원문에 없는 장단점을 추가합니다.
