# 용어와 문장 패턴

특정 프로젝트의 확인된 정의가 있으면 그 정의를 우선합니다.

## 용어 목록

용어 목록은 문서에서 혼동하기 쉬운 개념과 반복되는 기술 용어만 관리합니다.
목록 밖의 단어를 일괄 금지하지 않습니다.
한 문서의 임시 결정과 조직의 공식 승인을 구분합니다.
기존 용어집과 충돌하면 새로운 표현을 자동 승인하지 않습니다.

### 예제 용어 목록

아래 용어 결정은 예제 문서 범위의 임시 결정으로 취급합니다.

| 대표 용어 | 품사 | 정의 | 사용 예 | 사용하지 않는 대체 표현 | 상태 |
|---|---|---|---|---|---|
| 인증 | 명사 | 요청자가 제시한 신원을 점검하는 과정 | `인증에 실패하면 서버가 요청을 거부합니다.` | `본인 확인`, `로그인 검증` | 문서 내 임시 용어 |
| 인가 | 명사 | 특정 자원을 사용할 권한이 있는지 판정하는 과정 | `인가에 실패하면 서버가 요청을 거부합니다.` | `권한 확인`, `허가` | 문서 내 임시 용어 |
| 설정 저장 | 명사 (동사 `저장하다`) | 편집한 설정을 설정 파일에 기록하는 작업 | `설정을 저장하십시오.` | `설정 기록`, `설정 반영` | 문서 내 임시 용어 |
| 설정 적용 | 명사 (동사 `적용하다`) | 저장된 설정을 서버의 동작에 반영하는 작업 | `설정을 서버에 적용하십시오.` | `설정 반영`, `설정 배포` | 문서 내 임시 용어 |
| 닫다 | 동사 | 밸브나 회로의 흐름을 차단하는 동작 | `배수 밸브를 닫으십시오.` | `잠그다`, 회의나 계약의 종료를 뜻하는 `닫다` | 문서 내 임시 용어 |
| 확인 | 명사 (동사 `확인하다`) | 대상의 상태가 기준에 맞는지 점검하는 작업 | `압력계의 표시를 확인하십시오.` | 승인을 뜻하는 `확인` | 문서 내 임시 용어 |

### 하나의 단어, 하나의 의미

원문: `압력계의 표시를 확인하십시오. 작업 계획은 관리자의 확인을 받으십시오.`

교정: `압력계의 표시를 확인하십시오. 작업 계획에 관리자의 승인을 받으십시오.`

`확인`을 점검의 의미로 정했으므로 승인의 의미에는 `승인`을 사용합니다.

원문: `배수 밸브를 닫으십시오. 작업이 끝나면 작업 기록을 닫으십시오.`

교정: `배수 밸브를 닫으십시오. 작업이 끝나면 작업 기록을 완료 상태로 변경하십시오.`

`닫다`는 밸브와 회로에만 사용합니다. 작업 기록에 적용할 정확한 동작이 원문에 없으면 확인 사항으로 보고합니다.

### 한국어 활용

대표 동사가 `저장하다`이면 `저장하십시오`, `저장하면`, `저장했습니다`를 문맥에 맞게 사용합니다.
`저장됨`이라는 상태명과 `저장하다`라는 행동을 동일한 문장 역할로 취급하지 않습니다.
명사형이나 활용형을 탐지했다는 사실만으로 비승인 용어로 판정하지 않습니다.
대표 용어를 넣어 비문이 되면 문장 구조를 바꿉니다.

문서의 실제 UI 이름이 `Save changes`이면 해당 표기를 유지합니다.
본문에서 작업 개념을 서술할 때는 확인된 한국어 대표 용어를 사용합니다.
UI 문자열은 용어 통일의 대상으로 삼지 않으며 자동 번역하지 않습니다.

### 신규 용어 처리

기존 용어와 뜻이 같으면 기존 대표 용어를 사용합니다.
뜻이 다르면 별도 개념으로 기록합니다. 뜻이 불분명하면 원문을 유지하고 확인을 요청합니다.
조직의 승인 절차가 없으면 `문서 내 임시 용어`로만 사용합니다.
임시 용어가 핵심 작업의 해석을 결정하면 해당 절차를 확정된 실행 절차로 제시하지 않습니다.

## 종결형 통제

절차문의 지시는 `~하십시오`, 금지는 `~하지 마십시오`로 작성합니다.
설명문은 `~합니다`, `~했습니다`, `~할 것입니다`만 사용합니다.

| 원문 | 교정 |
|---|---|
| `백업 파일을 보관해 두도록 하십시오.` | `백업 파일을 보관하십시오.` |
| `케이블을 분리하지 않도록 합니다.` | `케이블을 분리하지 마십시오.` |
| `시스템이 로그를 기록하고 있게 됩니다.` | `시스템이 로그를 기록합니다.` |
| `점검 결과를 보고하기를 하십시오.` | `점검 결과를 보고하십시오.` |

`~기`와 `~음`은 `## 설정 저장하기` 같은 제목과 표의 항목명에만 사용합니다.

## 문장 길이

절차문은 15어절 이하, 설명문은 20어절 이하로 작성합니다.

### 조건, 행동, 결과 기준의 분리

원문: `점검 모드로 전환한 후 서비스 상태 페이지에서 오류 표시가 있는지 확인하고 오류 표시가 없으면 설정 파일을 서버에 적용한 다음 로그에서 적용 결과를 확인하십시오.`

교정:

1. 점검 모드로 전환하십시오.
2. 서비스 상태 페이지에서 오류 표시가 있는지 확인하십시오.
3. 오류 표시가 없으면 설정 파일을 서버에 적용하십시오.
4. 로그에서 적용 결과를 확인하십시오.

원문에 없는 오류 발생 시의 분기는 추가하지 않습니다.

### 상한 초과를 허용하는 경우

원문: `냉각수 온도가 40°C 이하이고 압력계가 0 kPa를 표시하는 동안에만 잠금 버튼을 누른 상태로 배수 밸브 손잡이를 돌리십시오.`

교정: 원문을 유지합니다.

검토 보고: `위치: 4단계. 규칙: 문장길이. 문제: 17어절입니다. 처리: 지속 조건이 버튼 유지와 손잡이 회전 전체에 적용되므로 분리하지 않았습니다.`

## 명사 연쇄 제한

수식 관계 없이 이어지는 명사는 세 개까지 허용합니다.

원문: `서버 설정 파일 백업 상태 점검을 수행하십시오.`

교정: `서버 설정 파일의 백업 상태를 점검하십시오.`

원문: `인증 서버 인증서 만료 일자 확인 결과 기록`

교정:

1. 인증 서버 인증서의 만료 일자를 확인하십시오.
2. 확인 결과를 기록하십시오.

원문: `백업 서버 로그 정리를 하십시오.`

대응: `백업 서버의 로그`인지 `백업과 서버 로그`인지 원문에서 판단할 수 없으므로 관계를 추정하지 않고 확인 사항으로 보고합니다.

## 생략 금지와 개조식 종결

본문에서 주어, 목적어, 서술어, 조사를 생략하지 않습니다.
`~함`, `~할 것`, `~요망`은 제목과 표의 항목명에만 사용합니다.

| 원문 | 교정 |
|---|---|
| `작업 전 전원 차단 요망.` | `작업하기 전에 전원을 차단하십시오.` |
| `설정 변경 시 관리자 승인 받을 것.` | `설정을 변경하려면 관리자의 승인을 받으십시오.` |
| `로그 파일 삭제하십시오.` | `로그 파일을 삭제하십시오.` |
| `서비스 정상 동작 확인함.` | 확인 주체가 문맥에 있으면 `점검자가 서비스의 정상 동작을 확인했습니다.`로 교정합니다. |

확인 주체가 문맥에 없으면 주체를 추가하지 않고 확인 사항으로 보고합니다.

## 행동과 설명의 분리

근거 정보:

`운영자는 설정 파일을 저장한 다음 서버를 다시 시작해야 한다.`

`서버는 시작할 때 저장된 설정 파일을 읽는다.`

### 작업 절차

작업자: 운영자.

1. 설정 파일을 저장하십시오.
2. 서버를 다시 시작하십시오.

### 동작 설명

서버는 시작할 때 저장된 설정 파일을 읽습니다.

동작 설명을 `설정 파일을 읽으십시오`라는 작업 지시로 변환하지 않습니다.
설정 저장과 서버 재시작을 `설정을 반영하십시오`로 통합하지 않습니다.

## 조건의 범위

### 한 행동의 조건

원문: `검증에 실패하면 요청을 거부합니다.`

설명: `검증에 실패하면 시스템이 요청을 거부합니다.`

이 교정은 시스템이 주체라는 문맥이 확인된 경우에만 적용합니다.
원문에 없는 검증 성공 시의 동작은 추가하지 않습니다.

### 여러 행동에 적용되는 조건

원문: `승인을 받은 경우에만 A를 제출한 다음 B를 제출하십시오.`

교정:

`승인을 받은 경우에만 다음 두 단계를 수행하십시오.`

1. A를 제출하십시오.
2. B를 제출하십시오.

조건이 첫 단계에만 적용되는 것처럼 서술하지 않습니다.
일회성 조건 확인을 지속적 감시로 확대하지 않으며, 지속 조건을 일회성 확인으로 축소하지 않습니다.
승인 상태의 평가 시점이 작업에 영향을 미치고 원문에 명시되지 않았으면 확인을 요청합니다.

### 필요조건과 충분조건

`관리자일 때만 실행할 수 있습니다`는 관리자 권한을 필요조건으로 서술합니다.
이 문장을 `관리자이면 실행할 수 있습니다`로 변경하지 않습니다.

### 조건 결합

둘 다 필요하면 `A와 B를 모두 충족하면`으로 서술합니다.
하나 이상이면 되는 경우에는 `A 또는 B 중 하나 이상을 충족하면`으로 서술합니다.
정확히 하나여야 하면 `A와 B 중 하나만 충족하면`으로 서술합니다.
원문의 `및/또는`이 위 세 가지 중 어느 뜻인지 근거 자료에서 확인합니다.
근거가 없으면 의미를 추측하여 선택하지 않고, 해당 단계를 확정하지 않으며 확인을 요청합니다.

## 순차 작업과 동시 작업

원문: `버튼을 누른 다음 레버를 당기십시오.`

교정:

1. 버튼을 누르십시오.
2. 레버를 당기십시오.

원문: `버튼을 누른 상태를 유지하면서 레버를 당기십시오.`

교정: `버튼을 누른 상태를 유지하면서 레버를 당기십시오.`

유지 상태가 작업의 구성 요소이므로 두 단계로 분리하지 않습니다.

## 판정 기준이 없는 작업

원문: `온도가 충분히 낮아지면 덮개를 여십시오.`

대응: 덮개를 열 수 있는 온도 기준이 원문이나 관련 자료에 있는지 확인합니다.
기준이 없으면 해당 작업의 확정을 보류합니다.
`30°C 이하`와 같은 값을 임의로 삽입하지 않습니다.

원문: `실패하면 몇 차례 다시 시도하십시오.`

대응: 재시도의 간격과 상한이 원문이나 관련 자료에 있는지 확인합니다.
없으면 미확정 사항으로 보고합니다.
`3회`, `5초 간격`, `지수 백오프`를 임의로 추가하지 않습니다.

## 안전 지시

경고, 주의, 안전 지시는 명확한 명령 또는 조건으로 시작합니다.
고정 문구가 아닌 경고에만 이 교정을 적용하며, 경고 등급은 변경하지 않습니다.

원문: `주의: 이 장비는 고전압을 사용하므로 커버를 열기 전에 전원을 차단해야 합니다.`

교정: `주의: 커버를 열기 전에 전원을 차단하십시오. 이 장비는 고전압을 사용합니다.`

원문: `경고: 고온의 냉각수로 화상을 입을 위험이 있으니 온도가 40°C를 초과할 때는 배수 밸브를 여는 것을 피하십시오.`

교정: `경고: 냉각수 온도가 40°C를 초과하면 배수 밸브를 열지 마십시오. 고온의 냉각수에 화상을 입을 수 있습니다.`

### 경고의 위치와 등급

원문:

`기존 설정 파일을 삭제하십시오.`

`주의: 설정 파일을 삭제하면 저장된 설정을 복구할 수 없습니다.`

교정:

`주의: 설정 파일을 삭제하면 저장된 설정을 복구할 수 없습니다.`

`기존 설정 파일을 삭제하십시오.`

경고를 해당 행동 앞으로 이동합니다. 이 경고의 내용을 다른 파일 삭제에 일반화하지 않습니다.
`주의`를 `위험`으로 변경하지 않으며, 근거 없이 백업이나 전원 차단 같은 추가 작업을 지시하지 않습니다.
고정 문구는 표현을 수정하지 않고 위치와 적용 범위만 검토합니다.

## 절대 금지 구문

한국어 출력과 이 패키지의 서술에서 아래 세 구문을 사용하지 않습니다.
원문에 이 구문이 있으면 아래 방식으로 교정합니다.
아래 `원문` 예시를 출력에 옮기지 않습니다.

### 상투적 대조 구문

금지 형태: `A가 아니라 B`, `단순한 A가 아닌 B`, `A라기보다는 B`, `A뿐만 아니라 B`.

수행할 행동을 먼저 서술하고, 금지 사항은 별도 단계나 별도 문장으로 서술합니다.
대상의 성격은 그 대상이 무엇인지를 긍정문으로 서술합니다.

원문: `설정 파일을 삭제하는 것이 아니라 보관하십시오.`

교정:

1. 설정 파일을 보관하십시오.
2. 설정 파일을 삭제하지 마십시오.

원문: `이 단계는 단순한 확인이 아닌 승인 절차입니다.`

교정: `이 단계는 승인 절차입니다.`

원문: `이 작업은 재시작이라기보다는 설정 다시 읽기입니다.`

교정: `이 작업은 설정 파일을 다시 읽습니다. 이 작업은 서버를 다시 시작하지 않습니다.`

원문: `로그뿐만 아니라 설정 파일도 백업하십시오.`

교정:

1. 로그를 백업하십시오.
2. 설정 파일을 백업하십시오.

### 사선 병기

금지 형태: `A/B`, `A / B`, `및/또는`, `을/를`, `통과 / 확인 필요 / 보류`.

본문과 견본에서 두 항목을 사선으로 병기하지 않습니다. 항목 간 관계를 `와`, `및`, `또는`, `중 하나`로 명시하거나 항목을 분리하여 서술합니다.
조사 견본에는 `을(를)`을 사용합니다.
코드, `/srv/app/config.toml`과 같은 경로, URL, 단위, 날짜, UI 문자열 안의 사선은 보호 문자열로 유지합니다.

원문: `설정을 저장/적용하십시오.`

교정:

1. 설정을 저장하십시오.
2. 설정을 서버에 적용하십시오.

원문 견본: `{대상}을/를 선택하십시오.`

교정 견본: `{대상}을(를) 선택하십시오.`

원문: `로그 및/또는 설정 파일을 백업하십시오.`

교정: 근거 자료에서 결합 방식이 `모두`, `하나 이상`, `하나만` 중 어느 것인지 확인합니다.
둘 다 필요하다고 확인되면 `로그와 설정 파일을 모두 백업하십시오.`로 서술합니다.
근거가 없으면 해당 단계를 확정하지 않고 확인을 요청합니다.

원문 견본: `판정: 통과 / 확인 필요 / 보류`

교정 견본: `판정: {판정 값}`. 판정 값에는 `통과`, `확인 필요`, `보류` 중 하나를 기재합니다.

### 양비론적 유보

금지 형태: `A일 수도 있고 B일 수도 있고 둘 다 아닐 수도 있습니다`, 결정 없이 끝나는 `상황에 따라 다릅니다`, 결정 없이 끝나는 `장단점이 있습니다`.

해당 단계를 확정하지 않고, 결정을 좌우하는 조건을 확인 사항으로 명시합니다. 결정을 임의로 만들지 않습니다.

원문: `재시작은 무중단 방식일 수도 있고 전체 재시작일 수도 있습니다. 상황에 따라 다릅니다.`

교정: 실행용 본문에서 해당 단계를 확정하지 않고, 검토 보고서에 다음과 같이 기록합니다.

`문제: 재시작 방식을 정하는 조건이 원문에 없습니다.`

`처리: 결정 조건과 조건별 재시작 방식을 확인하기 전까지 해당 단계의 확정을 보류합니다.`

원문이 결정 조건을 제시하면 조건문으로 변환합니다.

원문: `접속 중인 사용자가 있으면 무중단 재시작을 하고, 없으면 전체 재시작을 합니다. 장단점이 있습니다.`

교정:

1. 접속 중인 사용자가 있는지 확인하십시오.
2. 접속 중인 사용자가 있으면 무중단 재시작을 수행하십시오.
3. 접속 중인 사용자가 없으면 전체 재시작을 수행하십시오.

결정에 기여하지 않는 `장단점이 있습니다`는 삭제합니다.

## 실행용 문서와 검토 보고서

실행용 본문에는 확인되지 않은 값이나 빈 명령 인수를 넣지 않습니다.
검토 보고서는 본문과 분리합니다.

검토 예:

`위치: 3단계.`

`문제: 대기 종료 조건이 없습니다.`

`규칙: 구체지시.`

`판정: 보류.`

`처리: 종료 조건을 확인하기 전까지 삭제 단계의 확정을 보류합니다.`

`판정` 항목에는 `통과`, `확인 필요`, `보류` 중 하나를 기재합니다.
