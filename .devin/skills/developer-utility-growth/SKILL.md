# Developer utility growth

Design the brief for a free tool, generator, checklist, or other ungated resource that earns developer trust and downstream product trials. You write a brief in chat only. Nothing gets built or deployed, no form collects data, and no hidden gate, forced account, or tracking credential enters through this skill. Lead capture machinery, enrichment, and forced signup funnels are out of scope: any gate in your brief is explicit, minimal, and justified.

## What you need before you start

- `problem` (required): the developer problem the free resource solves in one session.
- `product` (required): how the resource relates to the paid or core product without becoming a demo wall.
- `constraints` (optional): hosting, maintenance, or brand limits the user names. When maintenance cost exceeds them, name the cut that fits or stop.

## Shaping the resource

1. State the instant value: what the user gets in the first session with no account. If no account-free instant value exists, say so and reshape the concept rather than hiding the product behind a form.
2. Name the shareable unit: the artifact, link, or output the user naturally passes on.
3. Draw the product boundary: adjacent help that earns trust, not a crippled product slice. Write plainly where free value ends and product value begins.
4. Decide gating openly: no-gate or soft-gate, with reasons, the data asked for, and the privacy implications. Hidden gates and forced accounts are refused.
5. Set attribution limits: how far brand and links go without polluting the output.
6. Define success signals from observable behavior the user can already measure (repeat use, shares, downstream product trials), naming the existing measurement source for each.

## What you hand over

A resource brief covering the problem, instant value, shareable unit, product boundary, gate decision with privacy notes, attribution rules, success signals, and open risks.
