# 한국어 기계 문체와 번역투 목록

교정과 검토에서 이 목록을 한 차례 대조합니다.

첫 절의 세 가지 구문은 출현 빈도와 관계없이 교정합니다. 나머지 항목에는 다음 판정 원칙을 적용합니다.

- 상투 표현 하나만으로 기계 문체로 판정하지 않습니다. 같은 표현이 문단마다 반복되거나 여러 유형이 중첩될 때 교정합니다.
- 목록의 표현이 정확한 의미를 담고 있으면 유지합니다. `다양한`이 실제로 여러 종류를 가리키고 `~을 통해`가 실제 경로나 수단을 가리키면 교정하지 않습니다.
- 교정은 문장 재구성으로 합니다. 단어를 동의어로 치환하지 않습니다. 예를 들어 `혁신적인`을 `획기적인`으로 바꾸지 않습니다.

출력 문체는 원문의 문체와 사용자의 지시를 따릅니다. 이 목록은 특정 종결 어미나 높임 수준을 강제하지 않습니다.

## 무조건 제거하는 세 가지 구문

상투적 대조 구문, 사선 병기, 양비론적 유보에는 밀도 기준을 적용하지 않습니다. 문서에 한 번만 나타나도 교정하며, 교정 결과와 에이전트 자신의 설명문에도 사용하지 않습니다. 교정할 때 원문의 사실, 부정의 범위, 확실성 수준은 그대로 유지합니다.

### 상투적 대조 구문

`A가 아니라 B` 형태로 원문에 없는 대조를 만들어 B를 부각하는 구문입니다. B를 평서문으로 서술합니다. 다른 대조 구문으로 치환하는 것은 교정으로 인정하지 않습니다. 독자가 A로 오독할 위험이 실제로 있을 때에 한해 부정을 별도 문장으로 덧붙입니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `A가 아니라 B입니다`: `이 기능은 파일을 삭제하는 것이 아니라 보관함으로 옮깁니다` | `이 기능은 파일을 보관함으로 옮깁니다. 파일을 삭제하지 않습니다.` |
| `단순한 A가 아닌 B`: `단순한 메모 앱이 아닌 협업 도구입니다` | `여러 사람이 같은 메모를 함께 편집할 수 있습니다.` (원문에 해당 기능이 있을 때) |
| `A라기보다는 B`: `오류라기보다는 설정 문제에 가깝습니다` | `설정 문제입니다.` 원문이 추정이면 `설정 문제로 보입니다.` |
| `A뿐만 아니라 B`: `읽기뿐만 아니라 쓰기도 지원합니다` | `읽기와 쓰기를 지원합니다.` |
| 수사적 `A 대신 B`: `복잡한 설정 대신 클릭 한 번으로 시작하세요` | `버튼 하나로 설정을 마칩니다.` (원문에 근거가 있을 때) |

실제로 한 값을 다른 값으로 교체하는 절차를 서술하는 `A 대신 B`는 상투적 대조 구문에 해당하지 않습니다. `기본 포트 대신 8080을 씁니다`는 그대로 둡니다.

### 사선 병기

두 개념을 사선(`/`)으로 나열하여 둘의 관계 해석을 독자에게 넘기는 표기입니다. 관계를 `와`, `및`, `또는`, `중 하나`로 명시합니다. 두 개념이 서로 다른 행위를 가리키면 문장을 분리하고, 같은 행위를 중복 표기한 것이면 하나만 남깁니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `확인/검토해 주세요` | `확인해 주세요.` (같은 행위의 중복일 때) |
| `설치/배포 전에` | 둘 다이면 `설치 및 배포 전에`, 둘 중 하나이면 `설치하거나 배포하기 전에` |
| `통과 / 실패 여부를 기록합니다` | `통과했는지 실패했는지 기록합니다.` |
| `읽기/쓰기 권한` | `읽기 권한과 쓰기 권한` |
| 조사 견본 `{name}을/를`, `{name}이/가` | `{name}을(를)`, `{name}이(가)` |

보호 문자열 안의 사선은 유지합니다. 코드와 경로(`/etc/app/config.yaml`), URL, 단위(`km/h`, `MB/s`), 날짜(`2026/10/30`), 고유 명칭(`TCP/IP`), 인용한 UI 문자열(`"저장/닫기"`)이 이에 해당합니다.

### 양비론적 유보

양쪽 가능성을 나열한 뒤 판단 없이 종결하는 구문입니다. 원문이 한쪽을 뒷받침하면 그 판단을 서술합니다. 뒷받침하지 않으면 판단에 필요한 확인 사항을 한 문장으로 서술합니다. 원문의 실제 불확실성은 같은 강도의 추정 표현 하나로만 유지합니다. 원문에 없는 결론을 만들지 않습니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `A일 수도 있고 B일 수도 있으며 둘 다 아닐 수도 있습니다` | 근거가 있으면 `원인은 A로 보입니다.` 근거가 없으면 `원인을 특정하려면 A와 B의 로그를 확인해야 합니다.` |
| 문단 끝의 `장단점이 있습니다`, `일장일단이 있습니다` | 원문이 뒷받침하는 판단을 씁니다. 예: `이 서비스에는 캐시를 켜는 편이 낫습니다.` (원문에 측정 결과가 있을 때) |
| `상황에 따라 다릅니다` | 원문에 있는 조건을 씁니다. 예: `하루 요청이 1만 건을 넘으면 캐시를 켜십시오.` 조건이 없으면 확인 사항을 씁니다. |
| `정답은 없습니다` | 삭제합니다. 판단이 필요한 글이면 확인 사항 한 문장을 남깁니다. |

## 행정 용어와 법령 문체의 어휘

같은 뜻의 일상어가 있으면 일상어로 교정합니다. 교체로 뜻이 달라지거나 해당 분야의 정식 용어가 손상되면 원문 표현을 유지합니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `금일`, `익일`, `명일` | `오늘`, `다음 날`, `내일` |
| `금번`, `차회` | `이번`, `다음 번` |
| `상기`, `하기` | `위`, `아래` |
| `수령하다`, `득하다` | `받다` |
| `기재하다`, `기입하다` | `적다` |
| `상이하다` | `다르다` |
| `경과하다` | `지나다` |
| `구비하다` | `갖추다` |
| `요하다` | `필요하다` |
| `소요되다`가 시간을 뜻함 | `걸리다` |
| `불가합니다` | `할 수 없습니다` |
| `협조 요망`, `참석 요망` | `협조해 주십시오`, `참석해 주십시오` |

법령, 약관, 계약서의 문구는 인용할 때 원문 그대로 둡니다. 일반 설명문에 쓰인 법령 문체는 다음과 같이 교정합니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `~하여야 한다` | `~해야 합니다` |
| `당해` | `그`, `이` |
| `~한 자` | `~한 사람` |
| `~에 의거하여` | `~에 따라` |
| `~에 한하여` | `~인 경우에만` |
| `~하지 아니한다` | `~하지 않습니다` |

의무를 서술하는 문장은 주체를 밝히고 `~해야 합니다`로 씁니다. `운전자에게는 주의 의무가 부과됩니다`는 `운전자는 주의를 기울여야 합니다`로 교정합니다.

## 실체를 가리는 완곡 표현

완곡 표현이 독자에게 불리한 사실을 가리면 실체를 직접 서술합니다. 실체는 원문이나 주변 문맥에서 확인된 범위까지만 서술하며, 확인되지 않으면 원문 표현을 유지하고 `확인 필요` 항목으로 남깁니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `일부 기능을 조정합니다` (기능 삭제가 확인될 때) | `○○ 기능을 삭제합니다.` |
| `요금 체계를 개선합니다` (인상이 확인될 때) | `○월 ○일부터 월 요금이 ○원에서 ○원으로 오릅니다.` |
| `서비스 운영 방식을 변경합니다` (종료가 확인될 때) | `○○ 서비스를 ○월 ○일에 종료합니다.` |
| `이용에 일시적인 불편이 있었습니다` (접속 장애가 확인될 때) | `○시부터 ○시까지 로그인할 수 없었습니다.` |
| `정책이 강화됩니다` (제한 추가가 확인될 때) | 새로 생긴 제한과 적용 대상을 서술합니다. |

비용, 위약금, 해지 제한, 자동 갱신, 개인정보 수집과 제공 같은 조건이 괄호나 각주에 있으면 본문으로 옮깁니다. 누가, 얼마를, 언제까지, 어떤 경우에 부담하는지를 문장 앞부분에 둡니다.

## 번역투 구조

영어 전치사와 구문을 한국어 조사로 직역하여 생기는 표현입니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `~에 대한`이 명사를 중첩 수식: `보안에 대한 이해에 대한 교육` | `보안을 이해하도록 돕는 교육` |
| 수단을 가리키지 않는 `~을 통해`: `이번 업데이트를 통해 속도가 빨라졌습니다` | `이번 업데이트로 속도가 빨라졌습니다` |
| `~에 있어서`, `~에 있어` | `채용에 있어서 중요한 것은` → `채용에서 중요한 것은` |
| 행위자를 표시하는 `~로부터`, `~에 의해` | `관리자에 의해 승인되었습니다` → `관리자가 승인했습니다` (주체가 확인된 경우에 한함) |
| 행위를 대신하는 `가지다`, `갖다` | `회의를 가졌습니다` → `회의했습니다`, `시간을 가지고 검토하겠습니다` → `천천히 검토하겠습니다` |
| 이중 피동 `되어지다`, `보여지다`, `불려지다` | `보여집니다` → `보입니다`, `생각되어집니다` → `생각합니다` |
| `~하는 것은 ~하는 것이다` | `중요한 것은 테스트를 먼저 쓰는 것입니다` → `테스트를 먼저 써야 합니다` (원문이 의무를 뜻할 때에 한함) |
| 불필요한 대명사 `그것`, `그들`, `그녀` | 앞 문장의 주어가 분명하면 생략합니다 |
| 습관적 복수 표지 `~들` | `여러 파일들을` → `여러 파일을` |
| `~에 위치한`, `~에 위치하고 있는` | `서울에 위치한 사무실` → `서울 사무실`, `서울에 있는 사무실` |
| 의무를 흐리는 `~할 필요가 있다` | 의무이면 `~해야 한다`, 권고이면 `~하는 것이 좋다`로 원문의 의미에 맞춥니다 |
| `~라고 할 수 있다`, `~라고 볼 수 있다` | 근거가 있으면 `~이다`로 단정하고, 없으면 원문 수준의 추정을 유지합니다 |

## 명사화와 형식 동사

동작을 명사화한 뒤 `진행`, `실시`, `제공`, `수행`, `이루어지다` 같은 형식 동사를 결합하는 표현입니다.

| 원문 표현 | 교정 표현 |
|---|---|
| `검토를 진행하겠습니다` | `검토하겠습니다` |
| `설치를 수행합니다` | `설치합니다` |
| `개선이 이루어졌습니다` | `개선했습니다`, 주체가 불명확하면 `개선되었습니다` |
| `사용이 가능합니다` | `사용할 수 있습니다` |
| `확인 후 진행 부탁드립니다` | `확인한 뒤 진행해 주세요` |
| `기능 제공을 위한 환경 구축 작업` | `기능을 제공할 환경을 만드는 작업` |

## 과장된 의미 부여와 판촉 어휘

근거 없이 중요성이나 품질을 과장하는 표현입니다. 근거가 있으면 근거를 서술하고, 없으면 삭제합니다.

자주 쓰이는 어휘: `혁신적인`, `획기적인`, `압도적인`, `탁월한`, `강력한`, `원활한`, `다양한`, `효과적으로`, `효율적으로`, `최적의`, `핵심적인`, `필수적인`, `한층`, `더욱더`, `보다`(비교 대상 없이), `차세대`, `게임 체인저`, `시너지`.

자주 쓰이는 구절: `중요한 역할을 합니다`, `큰 의미가 있습니다`, `새로운 지평을 엽니다`, `한 단계 도약`, `패러다임의 전환`, `빠르게 변화하는 오늘날`, `디지털 전환 시대에`, `~의 중요성은 아무리 강조해도 지나치지 않습니다`.

| 원문 표현 | 교정 표현 |
|---|---|
| `이 라이브러리는 개발 생산성 향상에 핵심적인 역할을 합니다.` | `이 라이브러리는 반복되는 설정 코드를 자동으로 만듭니다.` (원문 문맥에 해당 기능이 있을 때) |
| `빠르게 변화하는 오늘날, 보안의 중요성은 아무리 강조해도 지나치지 않습니다.` | 삭제합니다. 다음 문장이 실제 내용을 시작하면 그 문장부터 씁니다. |
| `보다 원활한 서비스 제공을 위해 점검을 실시합니다.` | `서비스 점검을 합니다. 점검 중에는 로그인할 수 없습니다.` (점검 영향이 원문에 있을 때) |

## 불특정 출처

`전문가들은 ~라고 말합니다`, `많은 연구에 따르면`, `업계에서는`, `일반적으로 알려진 바와 같이`처럼 출처를 모호하게 처리하는 표현입니다.
출처가 원문에 있으면 그 이름을 명시하고, 없으면 출처 표현을 삭제하고 주장의 확실성을 원문 수준으로 유지합니다. 출처를 만들어 내지 않습니다.

## 기계적 구성

상투적 대조 구문은 `무조건 제거하는 세 가지 구문`에서 다룹니다.

| 원문 표현 | 처리 |
|---|---|
| 습관적 세 항목 나열: `빠르고, 안전하고, 편리합니다` | 근거가 있는 항목만 남깁니다. 항목 수를 맞추기 위해 채우지 않습니다 |
| 문단마다 반복되는 `결론적으로`, `요약하자면`, `즉,` | 실제 요약 문단에만 씁니다 |
| 예고 문장: `이번 글에서는 ~에 대해 알아보겠습니다`, `자세히 살펴보겠습니다` | 삭제하고 본론으로 바로 시작합니다 |
| 자문자답: `왜 중요할까요? 바로 ~때문입니다` | `~때문에 중요합니다` |
| 문단마다 같은 구조: 주장, 부연, `이처럼 ~합니다` | 문단의 길이와 도입부를 내용에 맞게 달리합니다 |
| 제목을 반복하는 첫 문장 | 삭제합니다 |
| 습관적 맺음말: `앞으로가 기대됩니다`, `여러분의 성공을 응원합니다` | 삭제하거나 실제 후속 조치로 대체합니다 |
| 같은 대상의 지칭 변경: `이 도구`, `해당 솔루션`, `본 플랫폼` | 하나의 명칭으로 통일합니다 |

## 표기 관습

- 굵은 글씨가 문장마다 있거나 `**항목:** 설명` 형태의 목록이 이어지면 굵은 글씨를 제거하고 문단이나 표로 재구성합니다.
- 제목과 목록 앞의 장식용 이모지는 삭제합니다.
- 줄표(`—`)는 쉼표, 괄호, 마침표로 대체합니다.
- 따옴표는 문서 안에서 한 종류로 통일합니다. 코드와 UI 문자열 안의 따옴표는 변경하지 않습니다.
- 쌍점(`:`) 뒤에 짧은 문장을 붙이는 표기는 일반 문장으로 바꿉니다.

## 대화형 응답 표현

본문에 섞인 대화형 응답의 상투 표현은 모두 삭제합니다.

`좋은 질문입니다`, `물론입니다!`, `말씀하신 대로`, `도움이 되셨길 바랍니다`, `궁금한 점이 있으시면 언제든지 문의해 주세요`, `더 필요한 내용이 있으면 말씀해 주세요`, `아래에 정리해 드리겠습니다`, `제가 알기로는`, `현재 학습된 정보 기준으로`.

## 높임법 오류와 과잉 존대

이 절은 원문에 이미 있는 높임법의 오류를 교정하는 기준입니다. 원문에 없는 높임을 새로 추가하지 않습니다.

| 원문 표현 | 교정 표현 |
|---|---|
| 사물 존칭: `결제가 완료되셨습니다`, `주문하신 상품이 품절이십니다` | `결제가 완료되었습니다`, `주문하신 상품이 품절되었습니다` |
| 중복 높임: `하실 수 있으십니다`, `확인하시기 바라겠습니다` | `하실 수 있습니다`, `확인해 주세요` |
| 문장마다 반복되는 `~께서`, `~하시는` | 독자가 주어인 문장에서 한 번만 씁니다 |
| 압존 오류: 청자보다 낮은 대상을 높임 | 청자와 대상의 관계가 원문에서 확인될 때에 한해 교정합니다 |
| 사실 진술에 붙은 `~인 것 같습니다`, `~하는 듯합니다` | 근거가 확실하면 단정합니다. 원문이 추정이면 추정을 유지합니다 |
| 의무를 대신하는 `~해 주시면 감사하겠습니다` | 의무이면 `~해야 합니다`, 요청이면 `~해 주세요` |

## 문단 단위 교정 예

원문:

`안녕하세요! 오늘은 새로운 배포 도구에 대해 알아보겠습니다. 본 도구는 단순한 배포 도구가 아니라, 개발 생산성 향상에 핵심적인 역할을 하는 혁신적인 솔루션입니다. 이를 통해 사용자들은 보다 빠르고, 안전하고, 효율적인 배포가 가능합니다. 결론적으로, 이 도구는 여러분의 개발 여정에 큰 도움이 될 것입니다. 궁금한 점이 있으시면 언제든지 문의해 주세요!`

원문이 전달하는 사실은 새 배포 도구가 나왔다는 것 하나입니다. 속도와 안전성의 근거는 원문에 없습니다.

교정: `새 배포 도구를 소개합니다.`

원문 주변에 기능 설명(예: 설정 파일 하나로 여러 서버에 배포, 실패 시 이전 버전으로 복원)이 있으면 그 사실로 다음 문장을 작성합니다.

`설정 파일 하나로 여러 서버에 배포하고, 배포가 실패하면 이전 버전으로 되돌립니다.`

근거 없는 `빠르고 안전하다`는 쓰지 않습니다. 필요하면 `확인 필요: 속도와 안전성을 뒷받침할 자료가 있는지`를 별도로 기록합니다.
